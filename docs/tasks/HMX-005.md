# TASK HMX-005 — Component registry, schemas, validation, and rendering

**Phase:** 2 · **Assignee:** Codex · **Status:** in progress

## CONTEXT

HMX-004 landed directive syntax. Directives currently parse, validate nothing, and render
their children transparently with an `HMX2002` warning. This task turns that syntax into a
**component model**.

Binding: `CLAUDE.md`, `SPEC.md` §4.1–§4.2 and §5, `SECURITY.md`,
`docs/adr/0002-directive-syntax.md`, `docs/adr/0007-trust-modes.md`, and
`docs/research/prior-art.md` (the Markdoc section — schema discipline is the idea this task
takes from it).

This is the task the Phase 3 gate will judge. Markdown + directives with unvalidated string
attributes is decorated syntax. Schemas are what make it a component model a compiler can
check, an editor can complete, and a generator can target.

## OBJECTIVE

`:::note{type=warning}` validates against a declared schema, renders real HTML, and a typo
in either the component name or an attribute produces a diagnostic that names the problem
and suggests the fix.

## REQUIREMENTS

### 1. Schemas are data, renderers are code

**The schema MUST be JSON-serializable** — no functions, no classes, no symbols. This is
not a style preference: the schemas are intended to be exported later as JSON Schema and as
a generation grammar (`BACKLOG.md`, Research). A schema with a function in it cannot be
exported, and discovering that after adoption is expensive.

Rendering lives in a separate lookup keyed by component name.

```ts
export type AttributeType = 'string' | 'number' | 'boolean' | 'enum' | 'url' | 'identifier'

export interface AttributeSchema {
  readonly type: AttributeType
  /** Required when type is 'enum'. */
  readonly values?: readonly string[]
  readonly required?: boolean
  /** Applied when the attribute is absent. Must satisfy this schema. */
  readonly default?: string
  /** Inclusive bounds, numbers only. */
  readonly min?: number
  readonly max?: number
  /** One sentence, for diagnostics and future editor tooling. */
  readonly description: string
}

export type DirectiveKind = 'container' | 'leaf' | 'text'

export interface ComponentSchema {
  readonly name: string
  /** Forms this component may be written in. */
  readonly kinds: readonly DirectiveKind[]
  readonly attributes: Readonly<Record<string, AttributeSchema>>
  /** What may appear between the fences. 'none' forbids content. */
  readonly children: 'block' | 'phrasing' | 'none'
  readonly label: 'required' | 'optional' | 'forbidden'
  readonly description: string
}
```

Universal attributes `id`, `class`, and `title` are accepted on every component without
being declared, and MUST NOT require repetition in each schema.

### 2. Rendering contract

No template language. A renderer returns nested wrappers, outermost first:

```ts
export interface RenderedElement {
  readonly tag: string
  readonly attributes: Readonly<Record<string, string>>
}

export interface RenderPlan {
  /** Outermost to innermost. Children are emitted inside the last one. */
  readonly wrappers: readonly RenderedElement[]
  /** Wraps the label, emitted before children inside the innermost wrapper. */
  readonly labelWrapper?: RenderedElement
}

export type ComponentRenderer = (
  node: TextDirective | LeafDirective | ContainerDirective,
  attributes: ResolvedAttributes,
) => RenderPlan
```

`ResolvedAttributes` is the post-validation view: defaults applied, numbers parsed, enums
narrowed. Renderers MUST NOT see raw author strings — that is how injection reaches output.

### 3. Built-in components

Four containers and one text directive. Keep it at that: this proves the mechanism, and
every extra component is surface area to maintain before the design is settled.

| Name | Kind | Attributes | Renders |
|---|---|---|---|
| `note` | container | `type`: enum `info\|warning\|danger\|success`, default `info` | `<aside class="hmx-note hmx-note-{type}">`, label in `<p class="hmx-note-title">` |
| `card` | container | — | `<article class="hmx-card">`, label in `<h3 class="hmx-card-title">` |
| `grid` | container | `columns`: number 1–12 default 3; `gap`: number 0–16 default 4 | `<div class="hmx-grid" style="--hmx-grid-columns:{columns};--hmx-grid-gap:{gap}">` |
| `metric` | container | — | `<div class="hmx-metric">`, label in `<p class="hmx-metric-label">` |
| `badge` | text | `kind`: enum `info\|warning\|danger\|success`, default `info` | `<span class="hmx-badge hmx-badge-{kind}">` |

`label` is `optional` on all of them; `children` is `block` for containers and `phrasing`
for `badge`.

**No stylesheet is emitted.** Class names are hooks; styling is Phase 3. A document using
these components must still produce **zero JavaScript**.

### 4. Validation and diagnostics

Codes are permanent once shipped. Use exactly these; `HMX2001`, `HMX2002`, and `HMX2010`
already exist in `SPEC.md` and must keep their meanings.

| Code | Severity | Condition |
|---|---|---|
| `HMX2001` | warning | Unknown attribute on a known component. Include a suggestion when a declared name is within edit distance 2. |
| `HMX2002` | warning | Unknown component. Include a suggestion when a registered name is within edit distance 2. Renders children transparently, as today. |
| `HMX2003` | error | Required attribute missing. Name it and give its `description`. |
| `HMX2004` | error | Value not in an enum's `values`. List the permitted values; suggest the nearest. |
| `HMX2005` | error | Value fails its type — non-numeric `number`, out-of-range, non-`true`/`false` boolean, malformed `identifier`. |
| `HMX2006` | warning | Content not permitted by `children` — block content in a `phrasing` component, or any content in a `none` component. |
| `HMX2007` | error | Label required and absent, or present and `forbidden`. |
| `HMX2008` | error | Component written in a form not listed in `kinds`, e.g. `::card` when `card` is container-only. |
| `HMX2010` | warning | More than one `#id` shorthand; last wins. |

Every diagnostic MUST carry the span of **the offending attribute**, not the whole
directive — `Attribute.nameSpan` and `Attribute.valueSpan` exist for this.

Suggestions use Levenshtein distance ≤ 2, case-insensitive, choosing the single closest
candidate. Emit no suggestion rather than a bad one.

### 5. Attribute types

- `number` — parsed with `Number()`, must be finite; `min`/`max` inclusive.
- `boolean` — `true`, `false`, or bare (`{flag}` means `true`). Nothing else.
- `enum` — exact match against `values`, case-sensitive.
- `identifier` — must match `/^[A-Za-z][A-Za-z0-9_-]*$/`. This is what `id` uses.
- `url` — MUST pass the **same scheme allowlist the link emitter already uses** in
  `document` mode. Reuse that code; do not write a second URL checker that can drift from
  the first.
- `string` — any text, escaped at emission.

### 6. Security

This task is where author-controlled data first reaches HTML attributes, so it is the
highest-risk change since the sanitizer.

- `class` values MUST match `/^[A-Za-z0-9_ -]*$/`; reject with `HMX2005` otherwise. Do not
  attempt to escape arbitrary class text into an attribute.
- `id` uses the `identifier` rule.
- The `grid` `style` attribute is generated from **validated numbers only**. Author text
  MUST NOT reach a `style` attribute by any path. A test must assert that
  `:::grid{columns="3;background:url(javascript:alert(1))"}` produces `HMX2005` and emits
  no `style` containing author text.
- Every generated attribute value is HTML-escaped at emission regardless of validation.
  Validation is not a substitute for escaping.
- Component names come from the registry, never from the document, so a directive name can
  never become an arbitrary tag.
- Behaviour is identical in both trust modes except that `url` attributes follow the
  mode's scheme policy. State this in TSDoc.

### 7. Public API

```ts
export function compile(source: string, options?: CompileOptions): CompileResult
export interface CompileOptions { /* …existing… */ readonly components?: ComponentRegistry }
export const builtinComponents: ComponentRegistry
export type { ComponentSchema, AttributeSchema, ComponentRenderer, RenderPlan }
```

A caller may supply extra components. Supplying a registry **replaces** the built-ins only
if it declares the same names; otherwise the two merge, with caller entries winning. Do not
build a plugin system (ADR-0008) — this is a data argument, not a hook.

### 8. Tests

- Every built-in: valid use, each enum value, defaults applied when absent.
- Every diagnostic code above, asserting the code, the severity, and that the span points
  at the offending attribute rather than the directive.
- Suggestion quality: `:::mertic` suggests `metric`; `:::note{typ=warning}` suggests `type`;
  `:::note{type=warnign}` suggests `warning`. And a negative case — `:::zzzzzzzz` produces
  no suggestion rather than a nonsense one.
- The security cases in §6, including `Object.prototype` staying clean.
- Golden fixtures at `fixtures/markdown/components-*/` with `input.md`,
  `expected.ast.json`, `expected.html`.
- Output contains no `<script>` and no runtime, asserted in `tests/output-size/`.
- **CommonMark 652/652 and GFM 40/40 must still pass unchanged.**

## NON-GOALS

1. No CSS, no stylesheet emission, no design tokens — Phase 3.
2. No frontmatter — HMX-006.
3. No expressions in attributes — Phase 4. `HMX1010`/`HMX1011` behaviour stays as is.
4. No user-authored `.hmx` components — Phase 5.
5. No plugin API, no compiler hooks, no JSON Schema export yet. The export is *enabled* by
   keeping schemas serializable; it is not built here.
6. No state, events, or client JavaScript.

## EDGE CASES

- A component with an unknown attribute AND a missing required one: both diagnostics.
- `{#a #b}` — last wins, `HMX2010` warning.
- `{.x .y}` — classes combine in source order.
- An empty container: renders wrappers with no children, no diagnostic.
- `:::grid{columns=0}` and `{columns=13}` — both `HMX2005`.
- `:::grid{columns=3.5}` — decide, document, and test. Recommendation: reject.
- `badge` used as a container (`:::badge`) — `HMX2008`.
- A bare attribute on a `string`-typed attribute (`{title}`) — `HMX2005`, since `null` is
  not a string.
