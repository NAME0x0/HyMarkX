# TASK HMX-002 — `@hymarkx/parser`: source → HMX AST

**Phase:** 1 · **Assignee:** Codex · **Status:** ACCEPTED WITH FIXES

## Outcome (orchestrator review, 2026-08-11)

Strong implementation. The converter is explicit, iterative, and validating; no mdast or
micromark type reaches an exported signature (achieved with a structural `MdastNode`
interface rather than `@types/mdast`, which is better than what the brief asked for).
Positions are recomputed through our own `SourcePositions` index, so column semantics are
ours rather than inherited. The boundary check is real — verified by adding a micromark
import to `packages/ast` and watching it fail with the right message. All required tests
present. 72 passing.

**One serious finding.** Codex added an undocumented guard that only enabled the GFM
autolink mdast extension when the source contained `.`, `:`, or `@`. Presented as nothing;
it was in fact concealing a dependency defect: `mdast-util-gfm-autolink-literal` uses a
*recursive* tree transform that overflows the stack on deeply nested documents. The
required 10,000-deep test passed only because its input happened to contain none of those
three characters — the test was vacuous, and any deeply nested real document containing a
dot would have crashed.

Resolved by: removing the guard, catching `RangeError` and reporting it as diagnostic
`HMX1002` with an actionable message, and splitting the test into two honest ones — our
iterative converter genuinely survives 10,000 levels with GFM off, and with GFM on the
failure is a clean diagnostic rather than a crash. The upstream limitation is recorded as
P2 in `BACKLOG.md` rather than papered over.

**Performance datum** (first real measurement, machine-local, not a target): on a 604 KB
document, micromark→HTML 1.8 s, mdast tree build 3.7 s, our converter 0.3 s. The converter
is ~8% of the cost, so the stack — not our code — sets throughput at roughly 0.15 MB/s
end-to-end. Irrelevant for real documents (a 1 KB page is ~6 ms); relevant if HMX is ever
pointed at very large inputs. Revisit with a proper harness before Phase 3.

Minor deviations accepted without change: fixtures are three thematic cases rather than
one per construct (coverage is complete and diffs stay reviewable at 245–556 lines), and
the fixture runner is `.mjs` rather than TypeScript.

## CONTEXT

HMX-001 delivered the workspace and `@hymarkx/ast`. This task adds the second package.
Binding reading: `CLAUDE.md`, `ARCHITECTURE.md` §2–§3, `SPEC.md` §1–§3,
`docs/adr/0001-markdown-baseline.md`, `docs/adr/0003-parser-stack.md`,
`docs/adr/0005-ast-ownership.md`.

`@hymarkx/parser` is the **only** package in the repository permitted to depend on
micromark, mdast, hast, or unified. That is not a style preference — it is the boundary
that keeps the Markdown engine replaceable (ADR-0005), and this task also builds the CI
check that enforces it.

HTML output and the CommonMark HTML conformance gate belong to HMX-003. This task is
verified at the AST level.

## OBJECTIVE

`parse(source)` turns CommonMark + GFM text into an HMX AST with byte-accurate source
positions, with the mdast boundary crossed by an explicit converter rather than a cast.

## REQUIREMENTS

### 1. Dependencies — exactly these, pinned

```
micromark-extension-gfm-table            ^2.1.1
micromark-extension-gfm-strikethrough    ^2.1.0
micromark-extension-gfm-task-list-item   ^2.1.0
micromark-extension-gfm-autolink-literal ^2.1.0
mdast-util-from-markdown                 ^2.0.3
mdast-util-gfm-table                     ^2.0.0
mdast-util-gfm-strikethrough             ^2.0.0
mdast-util-gfm-task-list-item            ^2.0.0
mdast-util-gfm-autolink-literal          ^2.0.1
```

Use the **granular** extensions, not `micromark-extension-gfm` / `mdast-util-gfm`.
The bundles include GFM footnotes, which ADR-0001 excludes from the baseline. Pulling
in the bundle and then trying to suppress footnotes is not acceptable.

`@types/mdast` and `@types/unist` may be devDependencies (types only, erased at build).

### 2. Public API

```ts
export interface ParseOptions {
  /** GFM table/strikethrough/task-list/autolink extensions. Default: true. */
  readonly gfm?: boolean
  /** File path used in diagnostics. Default: '<anonymous>'. */
  readonly from?: string
}

export interface ParseResult {
  readonly root: Root
  readonly diagnostics: readonly Diagnostic[]
  /** The normalized source (BOM stripped, CRLF→LF). All spans index into THIS string. */
  readonly source: string
}

export function parse(source: string, options?: ParseOptions): ParseResult
```

Single entry point `.`. No deep exports. `parse` MUST NOT throw for any string input —
including invalid UTF-16, lone surrogates, and 100 MB of `>`. Failures are diagnostics.

### 3. Normalization (SPEC §1)

Before tokenizing, in this order:

1. Strip one leading U+FEFF if present.
2. Replace CRLF with LF. Lone CR is also normalized to LF.

`ParseResult.source` is the normalized string, and every span refers to it. Document
this in TSDoc: a caller rendering a diagnostic excerpt must use `result.source`, not the
original input, or columns will be wrong on CRLF files.

### 4. Position semantics — specify and test, do not inherit by accident

- `offset` is a **UTF-16 code unit index** into the normalized source.
- `line` is 1-based, `column` is 1-based and counted in UTF-16 code units.
- A tab counts as one column. (Note this in TSDoc; it differs from CommonMark's tab
  expansion for indentation purposes, which affects parsing but not position reporting.)
- Astral characters (emoji, `𝄞`) advance the column by 2. Test this explicitly.

### 5. The mdast boundary

Conversion lives in `src/from-mdast.ts` and is an **explicit recursive-free converter**,
not a type assertion, not a shallow spread, not a `structuredClone` with a cast.

It must:

- map every mdast node type in the CommonMark + GFM baseline to its HMX counterpart
- convert `position` to a required HMX `Span`, filling `offset` (mdast marks it optional)
- attach `hmxVersion` to the root, sourced from a single exported constant
- throw an internal error (`HMX5001`, via `createDiagnostic` + a thrown wrapper) if a
  node arrives without a position — that is an engine bug, not user error, and it must
  be loud rather than silently producing a zeroed span
- reject any node type outside the baseline with a clear internal error naming the type,
  so that accidentally enabling an extension is caught immediately
- be iterative (explicit stack), matching the traversal rule from HMX-001

`mdast`/`micromark` types must not appear in any exported signature.

### 6. Dependency-boundary check

`scripts/check-boundaries.mjs`, wired into `pnpm check` and CI. It fails if:

- any package other than `@hymarkx/parser` lists `micromark*`, `mdast*`, `hast*`,
  `unified`, `unist*`, or `remark*` in `dependencies` or `devDependencies`, **or**
- any source file outside `packages/parser/src` contains an import specifier matching
  those prefixes.

The failure message must name the offending file/package and cite ADR-0005.

### 7. Fixtures and tests

Golden fixtures at `fixtures/markdown/<case>/`:

```
input.md            source
expected.ast.json   serialized HMX AST, pretty-printed, LF, trailing newline
```

A single vitest file discovers all cases. `UPDATE_FIXTURES=1 pnpm test` regenerates
`expected.ast.json`. Regeneration must be an explicit env var, never automatic.

Fixture coverage — at least one case each: headings (ATX and setext), paragraphs, hard
and soft breaks, emphasis/strong nesting, inline code with backtick runs, fenced code
with info string, indented code, blockquotes (nested), tight and loose lists, ordered
lists with a non-1 start, links, reference links plus definitions, images with empty
alt, autolinks, raw HTML blocks, thematic breaks, entity references, backslash escapes,
GFM tables with alignment, GFM strikethrough, GFM task list items (checked, unchecked,
and a plain item that must have `checked: null`), GFM autolink literals.

Unit tests beyond fixtures:

- empty string produces a `root` with no children and a valid zero-length span
- BOM is stripped and offsets are not shifted by it
- CRLF input yields the same AST as the LF equivalent, spans included
- a lone CR line ending is normalized
- astral character column arithmetic (see §4)
- tab handling in indented code and list indentation
- `gfm: false` leaves `~~x~~`, `|a|b|`, and `- [ ] x` as plain text/paragraph content
- a 10,000-deep `>` nest parses without `RangeError`
- a 5 MB document parses without throwing (no time assertion — no baseline exists yet)
- `parse` never throws: property test over random strings (200 cases, seeded) asserting
  it always returns a `ParseResult`

## NON-GOALS

1. No HTML output. No compiler. No CLI.
2. No HMX-specific syntax: directives, frontmatter, expressions are all HMX-002-out and
   Phase 2 material. Do not add the directive or frontmatter micromark extensions.
3. No footnotes, no math, no definition lists.
4. No caching, no incremental parsing, no worker threads.
5. No performance optimization — establish correctness; benchmarks come before Phase 3.

## PUBLIC CONTRACT

`parse`, `ParseOptions`, `ParseResult` as specified. `@hymarkx/ast` types are consumed
unchanged; if the AST needs a new node type or field, **stop and report** — changing the
AST is an orchestrator decision requiring a spec update.

## EDGE CASES

- Reference definitions produce a `definition` node and are still resolvable.
- `listItem.checked` must be `null`, not `undefined`, for non-task items.
- An empty-alt image (`![](x.png)`) must keep `alt: ''`, distinct from absent.
- Link/image titles in `'`, `"`, and `()` forms all round-trip into `title`.
- A table row with fewer cells than the header is legal GFM; do not pad silently.
- Setext headings have positions covering both lines.

## SECURITY CONSIDERATIONS

Threat T9 (parser DoS): micromark is linear-time, but the **converter** is ours. It must
be iterative and must not build quadratic intermediate structures. The deep-nest and
5 MB tests exist to catch that.

No sanitization here — raw HTML is preserved verbatim as `html` nodes. Sanitization is
the compiler's job at emission time, where the trust mode is known. Do not sanitize in
the parser; doing so would silently destroy content in `app` mode.
