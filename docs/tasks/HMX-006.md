# TASK HMX-006 — Frontmatter

**Phase:** 2 (final task) · **Assignee:** Codex · **Status:** in progress

## CONTEXT

HMX-004 added directive syntax; HMX-005 made directives a schema-validated component
model. This closes Phase 2 by giving documents metadata.

Binding: `CLAUDE.md`, `SPEC.md` §4.3, `SECURITY.md`, `docs/adr/0005-ast-ownership.md`.

## OBJECTIVE

A document may open with a `---` delimited YAML block. Its parsed value appears on the
compile result, never in the HTML, and a malformed or hostile block produces a diagnostic
rather than an exception or a polluted object.

## AUTHORIZED AST CHANGE

This task is **explicitly authorized** to add one node type to `@hymarkx/ast`. This is the
only AST change permitted; anything else remains a stop-and-report condition.

```ts
/** A frontmatter block. Only valid as the first child of the root. */
export interface Yaml extends NodeBase {
  type: 'yaml'
  /** Raw text between the delimiters, excluding them. Unparsed. */
  value: string
}
```

Add it to `RootContent`, `Node`, and `NodeMap`, give it a builder, and add it to
`childrenOf` in `visit.ts` as a leaf (returns `undefined`). The existing exhaustiveness
guard will fail to compile until you do — that is the guard working.

**Rationale, for the record:** metadata could have been returned out-of-tree, but the AST
is required to represent what the author wrote (spans on everything, formatter later). An
AST that silently omits part of the source stops round-tripping, which breaks `hmx fmt`
before it is written.

## REQUIREMENTS

### 1. Parsing — raw extraction only

Add `micromark-extension-frontmatter@^2.0.0` to `@hymarkx/parser`. As with directives,
use the tokenizer and write the handler in `packages/parser/src/frontmatter.ts`. Do not add
`mdast-util-frontmatter`.

The parser produces a `yaml` node with the raw text and a correct span. **The parser MUST
NOT parse the YAML.** It has no opinion on the value; that belongs to the compiler, which
keeps the YAML dependency off the parser boundary.

Only `---` delimiters, only YAML, only at the very start of the document. A `---` block
appearing later is ordinary Markdown (thematic break or setext heading) and MUST stay so.

### 2. Compiler — value semantics

Add `yaml@^2.9.0` to `@hymarkx/compiler`. Parse with these options exactly:

```ts
{
  schema: 'core',        // YAML 1.2; no 1.1 oddities like `yes` meaning true
  merge: false,          // no `<<` merge keys
  customTags: [],        // no tag-driven object construction
  stringKeys: true,      // keys must be strings, not complex nodes
  uniqueKeys: true,      // duplicate keys are an error, not last-wins
  maxAliasCount: 10,     // billion-laughs guard; frontmatter never needs aliases
  version: '1.2',
}
```

Every one of those is load-bearing. Do not relax any of them for convenience.

The result is exposed as:

```ts
export interface CompileResult {
  // …existing…
  /** Parsed frontmatter, or undefined when the document has none. */
  readonly frontmatter?: FrontmatterValue
}

export type FrontmatterScalar = string | number | boolean | null
export type FrontmatterValue = {
  readonly [key: string]: FrontmatterScalar | readonly FrontmatterScalar[] | FrontmatterValue
}
```

### 3. Prototype safety

`yaml` documents no prototype-pollution guard, so we provide one. After parsing, rebuild
every mapping into a **null-prototype object** via `Object.create(null)`. Any key for which
`isForbiddenAttributeName` returns true (`__proto__`, `constructor`, `prototype`) MUST be
rejected with `HMX3007` and omitted.

Reuse `isForbiddenAttributeName` from `@hymarkx/ast`. Do not write a second list.

### 4. Validation

| Code | Severity | Condition |
|---|---|---|
| `HMX2020` | error | Frontmatter is not a mapping (a sequence, scalar, or empty document) |
| `HMX2021` | error | YAML syntax error. Map the library's error position back into a real document span — the offset is relative to the block, not the file. |
| `HMX2022` | error | A reserved key has the wrong type |
| `HMX3007` | error | Forbidden key name |

Reserved keys and their types, per `SPEC.md` §4.3:

| Key | Type |
|---|---|
| `title` | string |
| `description` | string |
| `layout` | string |
| `lang` | string |
| `draft` | boolean |

Unknown keys are preserved and MUST NOT produce a diagnostic — frontmatter is an open
namespace and consumers add their own fields.

An **empty** frontmatter block (`---\n---`) is valid and yields `undefined` frontmatter
with no diagnostic.

### 5. Output

Frontmatter MUST NOT appear in the HTML in any form, in either trust mode. It is data on
the result, not content. The emitter skips `yaml` nodes explicitly.

Do **not** generate `<title>`, `<meta>`, or a document shell. HMX emits fragments; the
document shell is Phase 7 (layouts). Frontmatter is plumbing for that, not a licence to
build it now.

### 6. CLI

`hmx check --json` and `hmx build --json` include the parsed frontmatter in their JSON
output. Human-readable output is unchanged.

### 7. Tests

- Valid frontmatter with every reserved key, plus custom keys preserved.
- Empty block; frontmatter-only document with no body.
- `---` later in the document stays a thematic break / setext heading — assert the
  conformance behaviour is untouched.
- Not-a-mapping cases: a sequence, a bare scalar.
- A YAML syntax error, asserting the span points into the real document, not offset 0.
- Reserved-key type violations for each key.
- `__proto__`, `constructor`, and `prototype` keys → `HMX3007`, with a test asserting
  `Object.prototype` is unpolluted afterwards.
- **A billion-laughs document** must produce `HMX2021` rather than hanging or exhausting
  memory. This is the test that matters most in this task.
- CRLF frontmatter; frontmatter preceded by a BOM.
- Golden fixture at `fixtures/markdown/frontmatter/`.
- Output contains no frontmatter text in either trust mode.
- **CommonMark 652/652 and GFM 40/40 unchanged.**

## NON-GOALS

1. No layouts, no HTML document shell, no `<meta>` generation — Phase 7.
2. No TOML or JSON frontmatter. YAML only.
3. No frontmatter schema system for user-defined keys — that is a much larger design and
   would duplicate component schemas badly if rushed.
4. No expressions or references inside frontmatter.
5. No use of frontmatter values by components. That is a data-flow design, Phase 4+.

## EDGE CASES

- `---` on line 1 with no closing delimiter: not frontmatter; stays Markdown.
- A document that is *only* `---\ntitle: x\n---` with no body.
- Windows line endings inside the block.
- A tab-indented mapping (YAML forbids tabs for indentation) → `HMX2021` with a useful span.
- Very large frontmatter (1 MB) must not be pathological.
- `title: 123` → `HMX2022`, since `title` is declared string.

## SECURITY CONSIDERATIONS

YAML is the most dangerous format this project has accepted so far. Three specific risks:

1. **Entity expansion** (billion laughs) — `maxAliasCount: 10` plus a required test.
2. **Tag-driven construction** — `customTags: []` and `schema: 'core'` prevent
   language-specific tags from constructing objects.
3. **Prototype pollution** — handled by the null-prototype rebuild in §3.

Threat model addition: this is the first *external data format* HMX parses. Record it in
`SECURITY.md` as a new row rather than assuming the existing rows cover it.
