# TASK HMX-008 — Expressions: grammar, checker, compile-time evaluation

**Phase:** 4 · **Assignee:** Codex · **Status:** in progress

## CONTEXT

Phases 0–3 are complete and the interactivity gate passed. `prototypes/interactivity/`
already contains a working restricted-expression parser and evaluator — **read it first**.
It is throwaway code, but it proved the approach and its shape is a reasonable starting
point.

Binding: `docs/adr/0004-expression-language.md` (what the language permits),
`docs/adr/0012-interpolation-syntax.md` (why `{{ }}` and why compile time), `SPEC.md` §4.2
and §4.5, `CLAUDE.md`.

## OBJECTIVE

`{{ title }}` in prose and `{title={site.name}}` in an attribute resolve against frontmatter
at compile time, with unknown identifiers reported as errors carrying suggestions — and a
document using them still ships **zero JavaScript**.

## REQUIREMENTS

### 1. The expression language

Implement exactly the subset in ADR-0004. Permitted:

- literals: number, single- and double-quoted string, `true`, `false`, `null`
- identifiers bound in scope
- member access `a.b` and index access `a[b]`
- unary `!`, `-`, `+`
- binary `+ - * / %`, `== != < <= > >=`, `&& || ??`
- ternary `? :`
- optional chaining `?.`
- parentheses, array literals, object literals

Prohibited, each with its own clear message: assignment, `new`, function and arrow
literals, `this`, template literals, tagged templates, `import`, `await`, generators, regex
literals, increment/decrement, comma operator, and **all function calls**.

The grammar MUST be a strict subset of JavaScript's expression grammar, so editors and
human intuition transfer (ADR-0004). Precedence and associativity MUST match JavaScript.

Where this task's needs and the prototype's implementation differ, the prototype is a
reference, not an authority — it lacked member access, comparison, ternary, and optional
chaining.

### 2. Scope

The scope is the document's frontmatter, and nothing else. No globals, no `Math`, no
`process`, no host objects — there is nothing to reach.

An identifier not present in frontmatter is a **compile error** (`HMX2040`), not
`undefined`. Include a suggestion when a frontmatter key is within edit distance 2.

Member access into a missing property is `HMX2041`, except when guarded by `?.`, which
yields `null`.

### 3. Text interpolation

`{{ expr }}` in any text position. Rules:

- Whitespace inside the braces is insignificant: `{{title}}` and `{{ title }}` are the same.
- `\{{` is a literal `{{`.
- `{{` inside a code span or code block is literal text. **This is the highest-risk
  requirement in the task** — a template sigil leaking into code samples would make HMX
  unusable for technical writing. Test both fenced and indented blocks and inline spans.
- An unterminated `{{` is `HMX1020`, reported at the opening, with recovery.
- Interpolation is a text-level construct, so it must survive inside emphasis, links, list
  items, headings, table cells, and directive labels.

Implement as a micromark extension in `@hymarkx/parser`, producing a new AST node. **You are
authorized to add exactly one node type** to `@hymarkx/ast`:

```ts
/** A `{{ expr }}` interpolation. The expression is unparsed at this stage. */
export interface Interpolation extends NodeBase {
  type: 'interpolation'
  /** Raw expression text between the braces, trimmed. */
  value: string
}
```

Add it to `PhrasingContent`, `Node`, `NodeMap`, a builder, and `childrenOf` as a leaf. The
exhaustiveness guard will fail to compile until you do. **No other AST change.**

Parsing the expression itself belongs to the compiler, not the parser — same division as
frontmatter.

### 4. Expression-valued attributes

`{title={site.name}}` becomes legal, replacing the `HMX1010` rejection from SPEC §4.2. The
value is an expression; the resolved result is then validated against the attribute's
declared schema type as if it had been written literally. A `number`-typed attribute
receiving a string result is `HMX2005`, exactly as today.

`HMX1010` is retired. Tombstone it in the diagnostics registry — codes are never reused.

### 5. Evaluation and output

- Evaluation happens at compile time. The result is HTML-escaped and written into the
  output.
- `null` and `undefined` results render as the empty string, not `"null"`.
- Numbers render via `String(n)`; `-0` renders as `0`; non-finite values are `HMX2042`.
- Objects and arrays reaching a text position are `HMX2043` — rendering `[object Object]`
  is never the right answer.
- **Zero JavaScript.** A document using expressions emits no `<script>`. Assert it.
- Deterministic: identical input yields byte-identical output.

### 6. Purity — the requirement that matters

The evaluator MUST be incapable of reaching a host object. Specifically:

- No `eval`, no `new Function`, no dynamic property lookup that can reach `__proto__`,
  `constructor`, or `prototype`. Reuse `isForbiddenAttributeName` from `@hymarkx/ast`.
- Member access on a frontmatter value must not expose inherited properties — frontmatter
  mappings are already null-prototype, and `a.toString` must be `HMX2041`, not a function.
- Index access with a computed key must apply the same rules.
- Evaluation must be total: no expression may loop forever or recurse unboundedly. Cap
  expression depth and report `HMX1021` beyond it.

**Fuzz corpus required.** Generate at least 10,000 random inputs — both random bytes and
grammar-guided mutations — and assert that every one either parses and evaluates purely, or
produces a diagnostic. None may throw an unhandled exception, hang, or return a function.
Commit the seed so failures reproduce.

### 7. Diagnostics

| Code | Severity | Condition |
|---|---|---|
| `HMX1020` | error | Unterminated `{{` |
| `HMX1021` | error | Expression nesting too deep |
| `HMX1022` | error | Syntax error in an expression, with a span pointing at the offending token |
| `HMX2040` | error | Unknown identifier; suggest a near frontmatter key |
| `HMX2041` | error | Property does not exist on the value |
| `HMX2042` | error | Non-finite numeric result |
| `HMX2043` | error | Object or array in a text position |
| `HMX2044` | error | Prohibited construct — name it (`function calls are not allowed`) |

Every diagnostic carries a span pointing **inside the expression**, not at the whole
interpolation.

### 8. Tests

- Every operator, with precedence and associativity checked against JavaScript's own
  evaluation of the same expression where the subset allows it.
- Every prohibited construct, each asserting its specific message.
- `{{` inside inline code, fenced code, and indented code stays literal.
- `\{{` escapes.
- Interpolation inside emphasis, a link, a heading, a list item, a table cell, a directive
  label.
- Unknown identifier with and without a near match.
- `a?.b` on a missing key yields empty, `a.b` errors.
- Attribute expressions resolving to each schema type, and to the wrong type.
- The fuzz corpus.
- Zero `<script>`, determinism, and **CommonMark 652/652 plus GFM 40/40 unchanged.**

## NON-GOALS

1. No state, no reactivity, no runtime evaluation — Phase 6.
2. No `@`-statement family, no `@if`/`@for`. That syntax decision stays open (ADR-0002).
3. No user-defined functions, no filters, no pipes.
4. No expressions in frontmatter itself.
5. No component props — Phase 5.
