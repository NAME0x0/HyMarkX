Verified independently rather than from test names:

- **Proportionality holds exactly.** A plain Markdown document emits 0 bytes of CSS. A

- **Scoping is correct end to end.** Elements carry `data-hmx-s-<hash>` and the rewritten

- A CSS syntax error produces `HMX2030` at a real document position (line 2, column 14),

- All three code blocks in `docs/guides/styling.md` compile with no errors — checked by

## OBJECTIVE

A document using built-in components looks correct with no configuration, an author can add
scoped CSS in `app` mode, and a static document still ships **zero JavaScript** with CSS
proportional to what it used.

## REQUIREMENTS

### 1. CSS on the result

```ts
export interface CompileResult {
  // …existing…
  /** Stylesheet for this document. Empty string when no styles are needed. */
  readonly css: string
}

export interface CompileOptions {
  // …existing…
  /** Emit CSS in a <style> element at the top of the HTML instead of separately. Default false. */
  readonly inlineCss?: boolean
}
```

HMX emits fragments, so CSS is returned separately by default and the host decides where it
goes. `inlineCss: true` is for single-file output.

### 2. Built-in component stylesheet — proportional

Author a small stylesheet for `note`, `card`, `grid`, `metric`, and `badge`. Emit **only the
rules for components the document actually uses**. A document with one `:::note` must not
receive `grid` rules.

Constraints:

- Modern, restrained, legible. This is a default, not a theme — no opinionated brand colours,
  no imported fonts, no CSS reset.
- Use `rem` and relative units. Respect `prefers-color-scheme: dark`.
- Use `:where()` for zero specificity, so authors override without fighting specificity.
- Grid must honour `--hmx-grid-columns` and `--hmx-grid-gap`, which the component already
  emits, and collapse to one column on narrow viewports.
- No `!important` anywhere.

### 3. Design tokens

Define the tokens the stylesheet uses as CSS custom properties on `:where(:root)` — colours,
spacing, radius, border. Emit them only when at least one component rule is emitted. Keep the
set small: a token nobody overrides is a token nobody needed.

Document them in `docs/guides/styling.md` (a new short guide), since tokens are the supported
customisation surface.

### 4. Author styles: `<style>` and `<style scoped>`

Available in **`app` mode only**. `document` mode continues to reject `<style>` with
`HMX3001`, unchanged.

- A plain `<style>` block is collected into `result.css` verbatim and removed from the HTML.
- `<style scoped>` is rewritten so its rules apply only within the document that declared
  them: every selector gains a `[data-hmx-s-<hash>]` attribute, and every element HMX emits
  in that document receives the matching attribute.
- The hash is derived from the document identity (`options.from` plus block index) and MUST
  be deterministic — identical input produces identical output, per SPEC §5.
- `:global(sel)` inside a scoped block emits `sel` unscoped.
- Scoping MUST handle: multiple selectors in a list, descendant and child combinators,
  pseudo-classes and pseudo-elements, `@media` and `@supports` blocks (scope the rules
  inside, not the at-rule), and `@keyframes` (do **not** scope keyframe selectors like
  `from`/`to`/`50%`).

Use `postcss@^8.5.26` for parsing. Do not hand-roll a CSS parser — ADR-0011 covers why. It
belongs to `@hymarkx/compiler` only; the boundary check must stay green.

### 5. Zero JavaScript

Adding styles must not add a single byte of JS. `tests/output-size/` must assert that a
document using every built-in component plus a scoped style block contains no `<script>`.

### 6. Diagnostics

| Code | Severity | Condition |
|---|---|---|
| `HMX2030` | error | CSS syntax error in a `<style>` block. Map postcss's position back into a real document span — the offset is relative to the block. |
| `HMX2031` | warning | `<style scoped>` in a document that emits no elements to scope |

`HMX3001` for `<style>` in `document` mode is unchanged.

### 7. Tests

- Each built-in renders with its rules present, and *only* its rules.
- A document with no components produces `css === ''`.
- Token block appears once, and only when component rules do.
- Scoped selectors: list, descendant, child, pseudo-class, pseudo-element, `@media`,
  `@supports`, `@keyframes` (unscoped keyframe selectors), `:global()`.
- Determinism: compiling the same source twice produces byte-identical CSS.
- Two different scoped blocks in one document get different hashes.
- `<style>` in `document` mode is still rejected with `HMX3001` and no CSS leaks into

- CSS syntax error produces `HMX2030` with a span pointing into the document.
- `inlineCss: true` places the CSS in a `<style>` element ahead of the content.
- Zero `<script>` in all of the above.
- Golden fixtures at `fixtures/markdown/styled-*/` with `expected.css` alongside the
  existing files.
- **CommonMark 652/652 and GFM 40/40 unchanged.**

### 8. Guide

`docs/guides/styling.md`: how to use the built-in components, the token list, how to
override, and how scoped styles behave. Short and concrete — examples over prose.

## NON-GOALS

1. No native style shorthand or utility-class DSL (ADR-0011 rejects it).
2. No sanitized author CSS in `document` mode — deferred, needs its own threat model.
3. No CSS Modules class rewriting, no CSS-in-JS, no Tailwind integration.
4. No theming system, no dark-mode toggle, no runtime style manipulation.
5. No minification of the emitted CSS.
6. No changes to `@hymarkx/ast` or `@hymarkx/parser`.

## EDGE CASES

- A `<style>` block containing `}` inside a string or comment.
- An empty `<style></style>`.
- A scoped block whose selector is only `:global(...)`.
- `@media` containing `@supports` containing rules.
- A selector already containing an attribute selector.
- CRLF inside a style block — spans must still be right.
- Two documents compiled in the same process must not share scope hashes unless their
  identity matches.
