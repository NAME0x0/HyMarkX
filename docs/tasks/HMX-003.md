and nothing was enforcing that for globals.

`scripts/check-boundaries.mjs` now also rejects `process`, `Buffer`, `__dirname`, and

Also corrected: `SOURCES.md` recorded a SHA-256 without saying it was the vendored file's
rather than upstream's. The file is re-serialized, so the hashes differ; provenance is now

Accepted without change: raw-HTML blocks containing a prohibited element are dropped
whole, taking adjacent safe content with them. This looks like data loss but matches

## REQUIREMENTS

### 1. `packages/compiler` → `@hymarkx/compiler`

Dependencies: `@hymarkx/ast`, `@hymarkx/parser`. Nothing else.

```ts
export type TrustMode = 'document' | 'app'

export interface CompileOptions {
  /** Host-selected. Never inferred from document content (ADR-0007). Default 'document'. */
  readonly trust?: TrustMode
  readonly from?: string
  readonly gfm?: boolean
}

export interface CompileResult {
  readonly html: string
  readonly diagnostics: readonly Diagnostic[]
  readonly source: string
}

export function compile(source: string, options?: CompileOptions): CompileResult
export function compileAst(root: Root, source: string, options?: CompileOptions): CompileResult
export function renderDiagnostic(d: Diagnostic, source: string, options?: { color?: boolean; from?: string }): string
export function renderDiagnostics(ds: readonly Diagnostic[], source: string, options?): string
```

Internal structure — keep these as separate modules, because Phase 2+ inserts passes
between them and an entangled emitter is the thing ADR-0006 is protecting against:

```
src/analyze/    semantic passes over the AST → Diagnostic[]  (near-empty in Phase 1)
src/transform/  lowering passes                              (empty in Phase 1)
src/emit/       Backend interface + the html backend
src/diagnostics/ renderer
```

Define the `Backend` interface from `ARCHITECTURE.md` §6 even though there is one
backend. Lowering logic belongs in `transform/`, never inside the backend.

### 2. HTML emission — must match cmark byte-for-byte

The emitter walks the HMX AST iteratively and appends to a string builder. Getting
conformance requires these rules exactly; they are the parts implementations usually get
wrong:

- **Text escaping:** `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`.
  Single quotes are **not** escaped in text. Apply in attribute values too.
- **URL handling** in `href`/`src`: percent-encode characters outside the set cmark
  leaves alone. cmark encodes bytes not in
  `A-Za-z0-9` plus `-_.~!*'();:@&=+$,/?#[]%` — and leaves an already-valid `%XX`
  sequence untouched rather than double-encoding it. Then HTML-escape the result.
- **Tight vs loose lists:** a loose list wraps item content in `<p>`; a tight list does
  not. Tightness comes from the parser's `spread` flags; do not recompute it.
- **Raw HTML** (`html` nodes) is emitted verbatim in `app` mode. See §4 for `document`.
- **Code blocks:** `<pre><code class="language-X">` where X is the first word of the info
  string, HTML-escaped; no class when there is no info string. Content ends with `\n`.
- **Hard break** → `<br />`. **Thematic break** → `<hr />`. Self-closing form with the
  space, matching cmark.
- **Block-level elements are separated by `\n`**; the document ends with a single `\n`
  when non-empty. Mismatched trailing newlines are the most common conformance failure —
  compare exactly, do not `.trim()` in the test.
- **GFM tables** → `<table><thead><tr><th align="…">`; alignment attribute omitted when
  the column has none.
- **GFM task items** → `<input type="checkbox" disabled="" checked="" />` per GFM output.
- Output is deterministic: no `Date`, no `Math.random`, no object-key iteration order
  dependence.

### 4. Trust modes

`document` mode (default) must, per `SECURITY.md`:

- reject `html` nodes containing `<script`, `<style`, `<iframe`, `<object`, `<embed`,
  `<form`, or any `on*` attribute → `HMX3001` / `HMX3002`, and drop the node
- sanitize remaining raw HTML against an allowlist of elements and attributes
  (define it in `src/emit/sanitize.ts` as a single exported table; keep it small and
  auditable — headings, text formatting, lists, tables, links, images, code, `br`, `hr`)
- restrict `href`/`src` schemes to `http`, `https`, `mailto`, and relative references.
  Anything else → `HMX3003` and the attribute is dropped, not emitted empty.
  Scheme detection must be robust against `java\tscript:`, `JaVaScRiPt:`, leading
  control characters, and HTML-entity-encoded colons.
- emit no `<style>` or `<script>` under any circumstance

`app` mode passes raw HTML through untouched and applies no scheme restriction.

No document construct may change the mode. There is nothing to implement for that — it
is a property of there being no such construct, and `tests/security/` asserts it stays
true.

### 5. Diagnostic rendering

`renderDiagnostic` produces the format in `ARCHITECTURE.md` §4:

```
error[HMX1023]: expression was not closed
  ┌─ dashboard.hmx:14:7
  │
14 │ :::card{title={user.name}
  │              ^ expected `}` before end of directive attributes
  │
help: :::card{title={user.name}}
```

- gutter width adapts to the largest line number shown
- multi-line spans underline the first line and mark continuation
- tabs in the source line are expanded to spaces so the caret aligns
- `related` spans render as additional framed excerpts
- colour only when `color: true` (the CLI decides based on TTY and `NO_COLOR`)
- a span pointing past end-of-file renders without crashing

### 6. `packages/cli` → `@hymarkx/cli`

Binary `hmx`. Only package permitted to import `node:` builtins. No CLI framework
dependency — argument parsing with `node:util`'s `parseArgs`.

```
hmx build <input...> [--out <dir>] [--trust document|app] [--no-gfm] [--json]
hmx check <input...> [--trust document|app] [--no-gfm] [--json]
hmx --version | --help
```

- `build` writes `<name>.html` next to the input, or into `--out` preserving relative
  paths. `--out -` writes to stdout.
- `check` parses and analyses, writes nothing.
- `--json` prints `{ diagnostics: Diagnostic[] }` to stdout, machine-readable, with all
  human output suppressed.
- Exit codes: `0` success (warnings allowed), `1` at least one error-severity diagnostic,
  `2` usage error or I/O failure. Nothing else.
- A summary line to stderr: `2 errors, 1 warning in 3 files`.
- Refuse to write outside `--out`/the input directory (threat T10): resolve and verify
  the target stays within the intended root, and reject otherwise with `HMX3006`.
- Accepts `.md` and `.hmx`; any other extension is `HMX5002`.

## PUBLIC CONTRACT

The `compile` / `compileAst` / `renderDiagnostic` signatures and the CLI surface above.
`@hymarkx/ast` and `@hymarkx/parser` are consumed unchanged; needing to change either is
a stop-and-report condition.

## EDGE CASES

- Empty document → empty string, exit 0, no diagnostics.
- A document that is only raw HTML, in both trust modes.
- `--out` pointing at a nonexistent directory: create it, but only under the resolved root.
- Two inputs producing the same output path: `HMX5003`, do not silently overwrite.
- CRLF input: emitted HTML uses LF, and diagnostics columns are correct.
- Astral characters in link text and headings survive escaping unchanged.
- A 5 MB document compiles without exhausting memory.
