# TASK HMX-010 — State, events, and the minimal runtime

**Phase:** 6 · **Assignee:** Codex · **Status:** ACCEPTED — Phase 6 complete

## Outcome (orchestrator review, 2026-08-16)

Accepted without fixes. 1,048 tests, CommonMark 652/652 and GFM 40/40 unchanged,
`packages/parser` and `packages/ast` untouched.

**Component-local state works** — the requirement most likely to be got subtly wrong.
Driven in jsdom with two `:::Counter` instances: `[0,0]` → three clicks on the first →
`[3,0]` → one click on the second → `[3,1]`. Independent, verified directly rather than
asserted.

**Runtime measured at 591 bytes gzipped** against a 1.5 KB budget (992 raw). A document with
no interactive construct emits **0 bytes** and no `<script>`. Initial values are rendered
into the HTML, so the page is correct with JavaScript disabled.

**The security boundary holds, which is what permits interactivity in `document` mode.**
`window`, `document`, `globalThis`, `self`, and `fetch` are all rejected at compile time —
as *unknown identifiers*, because the scope is closed and there is nothing to reach. That is
ADR-0004's payoff arriving exactly as designed. `constructor` is `HMX2044`. Assignment
outside a handler, or to an undeclared name, is `HMX2061`. A non-allowlisted event is
`HMX2060`. No `eval`, no `new Function`. `document` and `app` mode emit byte-identical
JavaScript, so there is no hidden escape hatch in the trusted path.

Two things Codex added that were not asked for and are worth keeping: `tests/guides/`, a
suite that compiles the documentation examples so the guide cannot drift from the language,
and a dedicated `tests/output-size/interactivity-runtime.test.mjs` that makes the byte budget
a visible number in the diff.

## What this phase does *not* deliver

Stated plainly so it is not overclaimed: no named derived state, no shared state between
siblings, no async, no effects or lifecycle hooks. The dependency table is a tree of
state→view edges by design (ADR-0014). Interactivity here is a counter, a toggle, a filter —
not an application with a data layer.

## OBJECTIVE

```md
::state{count=0}

:::button{on-click="count = count + 1"}
Increment
:::

Count is {{ count }}.
```

compiles to HTML that is correct before any script runs, plus a runtime under budget that
updates only the marked node — and two uses of the same component count independently.

## REQUIREMENTS

### 1. Declaration

`::state{name=value}` declares reactive state. Multiple attributes declare multiple names.
Values are string, number, boolean, or null — the scalars expressions already handle.

Declared names join the expression scope alongside props. A name colliding with a prop is
`HMX2062` (error): one name, one meaning.

`::state` outside a document or component root — nested inside a directive — is `HMX2063`.

### 2. Component-local ownership

Each **expansion** of a component owns its state. Two `:::Counter` uses count
independently. The page document is the outermost component; nothing special-cases it.

State MUST NOT be visible to child components. A child sees only its props. There is no
ambient store.

This is the requirement most likely to be got subtly wrong, so test it directly: two
instances, mutate one, assert the other is unchanged in the rendered DOM.

### 3. Compiled dependency table

The Phase 4 checker already resolves which names each expression reads. Emit that as a
table mapping state name → the text and attribute positions depending on it.

Mark those positions in the HTML (an attribute such as `data-hmx-t="0"` is fine — match the
prototype's approach unless you have a better one). On mutation the runtime updates exactly
those nodes. **No virtual DOM, no diffing, no re-render.**

Named derived state is out of scope (ADR-0014). A dependency table with only state→view
edges is a tree, which is why this phase is tractable — do not add state→state edges.

### 4. Events

Allowlisted attributes only: `on-click`, `on-input`, `on-change`, `on-submit`, `on-focus`,
`on-blur`, `on-keydown`. Any other `on-` attribute is `HMX2060` (error).

Inside a handler — and only there — assignment to a declared state name is legal. This is
the single carve-out from ADR-0004. Assignment to anything else is `HMX2061` (error).
Extend the existing expression parser with an assignment production gated on handler
position; do not fork the parser.

`on-input` on an input element must also read the element's value into state, or two-way
binding is impossible. Keep this narrow: the value, as a string, coerced to the declared
state type.

### 5. Emission and proportionality

- Initial state values are rendered into the HTML at compile time. The page is correct with
  JavaScript disabled.
- The runtime is emitted **once** per document, inline, containing only the features used.
  A document with clicks but no inputs must not carry input handling.
- A document with no interactive construct emits **zero** bytes of runtime. Assert it.
- `CompileResult` gains `js: string`, empty when nothing is interactive, alongside the
  existing `css`. `inlineJs` mirrors `inlineCss`.

### 6. Runtime constraints — this is a security boundary

Interactivity is permitted in **both** trust modes (ADR-0014, SPEC §4.7). That is only safe
because the runtime exposes nothing:

- no `eval`, no `new Function`, anywhere
- no DOM handle, no `document`/`window` reachable from a handler
- no network, no storage, no timers, no globals
- a handler may read and assign declared state, and nothing else

A test must assert that a handler expression attempting `window`, `document`, `fetch`, or
`localStorage` is rejected at compile time by the existing expression checker.

### 7. Byte budget

**1.5 KB gzipped** for the full feature set, asserted in `tests/output-size/` as a failing
test with the measured number visible in the diff. The prototype's counter runtime was
367 bytes; this budget is generous, and it exists so that growth is a decision rather than
an accident.

## NON-GOALS

1. No named derived state (ADR-0014).
2. No shared or ambient state between siblings.
3. No SSR framework, no islands configuration, no partial hydration strategy.
4. No async, no data loading, no fetch — Phase 9+ at the earliest.
5. No lifecycle hooks, no effects, no watchers.
6. No parser or AST change. `::state` and `on-click` already parse; verify before assuming
   otherwise, and stop and report if a change seems required.

## EDGE CASES

- `::state` with no attributes.
- A state name shadowing a built-in component attribute such as `class`.
- Mutating state in a handler on a component that also passes props to a child.
- An input whose declared state is a number, receiving non-numeric text.
- A handler that assigns the same value repeatedly — no redundant DOM writes.
- A document with twelve interactive components: one runtime copy, twelve state scopes.
- Interpolation of a state value inside an attribute, not just text.
