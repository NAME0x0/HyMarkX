# TASK HMX-012 — `hmx dev`

**Phase:** 7 · **Assignee:** orchestrator (Codex quota exhausted) · **Status:** DONE

## Outcome (2026-08-17)

Implemented directly. 1,095 tests green, conformance unchanged.

`hmx dev` watches a directory, compiles documents on request, serves them with CSS and any
runtime inlined, and reloads open browsers on change.

## Decisions taken while building

**Compile per request; no build cache.** The obvious design is to build everything up front
and invalidate on change. Compiling on request removes cache invalidation as a category of
bug, and the measurements from ADR-0015 say it costs about 11 ms for a 2 KB page. The
watcher exists only to push reload events.

**Dependency inverted so resolution is not duplicated.** `dev.ts` receives a
`compileDocument` callback rather than importing the CLI's component resolution — which
would have been circular — or reimplementing it, which would let a page render differently
under `dev` than under `build`. The server serves; the CLI resolves.

**Server-sent events rather than a socket.** No dependency, and reload is one-directional.

**Bound to loopback.** The server compiles local files and can be run in `app` trust mode;
it has no business being reachable from a network.

## Verified by hand as well as by test

- Routing: `/` → `index.hmx`, `/other` → `other.md`, directory indexes, static assets, 404.
- Authored components expand and scoped CSS is inlined.
- **`hmx build` output contains no reload client** — checked for static *and* interactive
  documents, since that is the ADR-0015 requirement that protects output proportionality.
- Path traversal refused: `/../../../etc/passwd` and `/..%2f..%2fpackage.json` both blocked,
  with no file contents leaked.
- Server shuts down cleanly, releasing the watcher and open event streams.

## Known limitations

- The watcher reloads on any file change in the tree; it does not work out which pages were
  affected. At project scale that is cheap, and getting it wrong would mean stale pages.
- No HTTPS, no configurable host. Both would only matter if the server were meant to be
  reachable, which it is not.
- `--out` doubles as the port flag rather than introducing `--port`, to avoid growing the
  option surface for one command. Worth revisiting if `hmx dev` gains more options.
