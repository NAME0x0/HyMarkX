# TASK HMX-004 — Directive syntax: parsing, spans, and transparent rendering

**Phase:** 2 · **Assignee:** Codex · **Status:** in progress

## CONTEXT

Phase 1 is complete: `@hymarkx/{ast,parser,compiler,cli}` compile CommonMark + GFM to HTML
at 652/652 conformance with a working trust boundary. This is the first HMX-specific
syntax to enter the language.

Binding: `CLAUDE.md`, `SPEC.md` §4.1–§4.2, `docs/adr/0002-directive-syntax.md`,
`docs/adr/0003-parser-stack.md`, `docs/adr/0005-ast-ownership.md`.

This task is **syntax only**. Component schemas are HMX-005 and frontmatter is HMX-006.
Do not build them here.

## OBJECTIVE

`:::card{#hero .large title="Revenue"}` parses into the directive nodes already defined in
`@hymarkx/ast`, with a real source span on every attribute, and compiles to HTML that
degrades transparently because no component registry exists yet.

## REQUIREMENTS

### 1. Tokenizer: reuse, but own the tree

Add `micromark-extension-directive@^4.0.0` to `@hymarkx/parser`. Use its **tokenizer**.

**Do NOT use `mdast-util-directive`.** It exposes attributes as a plain
`Record<string, string>` with no positions, and our `Attribute` type requires `position`,
`nameSpan`, and optional `valueSpan`. Diagnostics that cannot point at the offending
attribute are the thing we are trying not to build.

Write our own `fromMarkdown` handlers in `packages/parser/src/directives.ts`. The token
stream carries every part separately, verified against the extension source:

```
directiveContainerName          directiveLeafName          directiveTextName
directiveContainerLabel         …LeafLabel                 …TextLabel
directiveContainerLabelString   …LeafLabelString           …TextLabelString
directiveContainerAttributes    …LeafAttributes            …TextAttributes
directiveContainerAttribute     …LeafAttribute             …TextAttribute
directiveContainerAttributeId          (shorthand `#id`)
directiveContainerAttributeClass       (shorthand `.class`)
directiveContainerAttributeName
directiveContainerAttributeInitializerMarker
directiveContainerAttributeValue
directiveContainerAttributeValueData
directiveContainerAttributeValueLiteral
directiveContainerAttributeValueMarker
```

Enter/exit events carry token positions; build `Attribute` records from them.

### 2. Node shape

Populate the existing `TextDirective`, `LeafDirective`, `ContainerDirective` types. Do not
change `@hymarkx/ast` — if you believe a change is needed, stop and report.

Note the deliberate divergence from `mdast-util-directive`: **the label is an explicit
`label` field**, not a first child paragraph tagged `data.directiveLabel`.

Attribute rules:

- Order and duplicates are preserved; `AttributeList` is an array, not a record.
- `{a}` (bare) yields `value: null`; `{a=""}` yields `value: ''`. Never conflate them.
- `{#hero}` yields `name: 'id'`, `{.big}` yields `name: 'class'`. Both keep the span of
  the shorthand as written, including the `#` or `.`.
- Multiple `.class` shorthands stay as separate attributes; combining is a rendering
  concern, not a parsing one.
- An attribute whose name satisfies `isForbiddenAttributeName` (`__proto__`,
  `constructor`, `prototype`) MUST produce diagnostic `HMX3005`, and the attribute MUST be
  dropped from the list. This is threat T8.

### 3. Syntax rules to honour (SPEC §4.1, normative)

- Name matches `[A-Za-z0-9](?:[A-Za-z0-9_-]*[A-Za-z0-9])?`.
- No whitespace between colons and name, name and label, or label and attributes.
- `:name:` is NOT a directive — emoji shortcodes must survive. Add a test with `:tada:`.
- A container's closing fence needs at least as many colons as the opening fence.
- An **unclosed container** produces `HMX1001` pointing at the opening fence, with a
  `related` span at end of document, and recovers by closing it at EOF. Recovery is
  required: one unclosed fence must not discard the rest of the document.

### 4. Escaping and interaction

These are where superset languages break. Each needs a test:

- `\:::card` is literal text, not a directive.
- A `:::` line inside a fenced code block is code, not a directive.
- A `:::` line inside an indented code block is code.
- Directives nest: `::::outer` containing `:::inner` containing content.
- A container directive inside a blockquote and inside a list item.
- A text directive inside emphasis, and inside a link's text.
- A directive name immediately followed by punctuation (`:x.`, `:x,`).
- Attribute values containing `}`, quotes, and backslash escapes.

### 5. Compiler: transparent degradation

No component registry exists yet (HMX-005). Until then, per SPEC §5:

- A container or leaf directive emits diagnostic `HMX2002` (**warning**, not error) naming
  the unknown component, and renders **its children** with no wrapper element.
- A text directive renders its children inline, same warning.
- A label, when present and unrendered, is not silently discarded — render it as the
  leading inline content of the fallback output.
- Directive attributes MUST NOT reach the HTML output. Nothing is allowlisted yet, and
  passing author-supplied attribute names into HTML is how an injection lands.

Exit code stays `0`, because warnings are not errors.

### 6. Tests

- Golden fixtures at `fixtures/markdown/directives-*/` following the existing pattern
  (`input.md`, `expected.ast.json`, `expected.html`).
- A dedicated span test asserting exact line/column/offset for every attribute in
  `:::card{#hero .large title="Revenue" bare}` — this is the requirement most likely to be
  quietly approximated.
- Every escaping and interaction case in §4.
- `HMX1001` unclosed recovery, `HMX3005` prototype-pollution rejection, `HMX2002` unknown
  component.
- **The CommonMark 652 and GFM suites must still pass unchanged.** Directives are enabled
  by default in the parser; if enabling them changes any conformance result, the syntax
  interacts with Markdown and that is a stop-and-report finding, not something to adjust
  the suite for.

## NON-GOALS

1. No component registry, no schemas, no attribute type validation — HMX-005.
2. No frontmatter — HMX-006.
3. No expressions in attribute values. `{title={user.name}}` MUST be rejected with
   `HMX1010` rather than treated as a literal string (SPEC §4.2).
4. No built-in components, no CSS, no runtime.
5. No changes to `@hymarkx/ast`.

## EDGE CASES

- Empty attribute block `{}` is legal and yields an empty list.
- `:::card` with no attributes and no label.
- A directive as the very first and very last line of a document.
- CRLF input: attribute spans must be correct against the normalized source.
- An astral character inside an attribute value — column arithmetic per HMX-002 §4.
- A container fence with trailing whitespace after the name.

## SECURITY CONSIDERATIONS

Threat T8 (prototype pollution) is the live one: `{__proto__=polluted}` must produce
`HMX3005` and must never reach `toAttributeRecord`. Add a test asserting
`Object.prototype` is unpolluted afterwards.

Threat T1/T3: attributes are author-supplied and must not be emitted as HTML attributes
by the fallback renderer. Add a test with `{onclick="alert(1)"}` asserting `onclick` does
not appear in the output.
