# TASK HMX-013 — Language server and VS Code extension

**Phase:** 7 (final task) · **Assignee:** orchestrator (Codex quota exhausted) · **Status:** DONE

## Outcome (2026-08-17)

Implemented directly. 1,125 tests green, conformance unchanged. Phase 7 complete.

`@hymarkx/language-server` provides diagnostics, completion, hover, and formatting over LSP.
`editors/vscode` contributes the `.hmx` language, a TextMate grammar, and a thin client.

## Decisions taken while building

**No `vscode-languageserver` dependency.** The needed subset is a `Content-Length` header
and a JSON body. Hand-writing it is about eighty lines and keeps a package that must stay
stable across editor versions at zero dependencies.

**`handle()` is a pure function of message plus document state.** The protocol can then be
driven directly in tests without spawning an editor, which is why fifteen protocol tests
exist rather than none. Transport is a separate, thin layer.

**Completion and hover read the component registry**, per ADR-0015 — no second catalogue to
drift. Attribute completion takes priority inside a brace block, because component names are
never what an author wants there.

**Node access via `import process from 'node:process'`, not the global.** The CLI declares a
global `process`; two global declarations in one typecheck program collide, while `tsc -b`
builds each package alone and cannot see the other's declaration. A module import makes each
host package's Node surface its own. This is the same class of leak found in HMX-003.

## Boundary change

`scripts/check-boundaries.mjs` now treats `@hymarkx/language-server` as a host package
alongside the CLI, and scopes the Node-builtin rule to `packages/` — an editor extension is
host code by definition, so `editors/` was never in scope for a browser-safety rule.

While making that change I corrupted the guard so `isPackageSource` was always false, which
silently disabled it. It reported success. Caught by re-running the deliberate-violation
check rather than trusting the green line — the same discipline applied to Codex's work
applies to mine.

## Verified

- Fifteen protocol tests: capabilities, diagnostics on open and change, completion in three
  positions, hover hit and miss, formatting, unknown-method error, and message framing
  including split chunks, two messages in one chunk, a malformed body, and
  `Content-Length` counted in **bytes** rather than code units — the classic hand-rolled-LSP
  bug.
- Driven over real stdio as a subprocess: initialize, `publishDiagnostics` with `HMX2002`,
  and eight completion items including `note`.
- Fifteen extension-asset tests: every grammar regex compiles, sample directives match, an
  escaped `\{{` does not, and the manifest's file references resolve.

## Known limitations

- No go-to-definition, references, rename, or semantic tokens. Each needs a project model —
  knowing every document rather than the open ones — which the server does not have.
- The VS Code client is untested in CI; running it needs an Extension Development Host.
  Its assets are tested; its behaviour is not.
- The grammar highlights frontmatter by embedding `source.yaml`, which requires an editor
  that ships the YAML grammar. VS Code does.
