# TASK HMX-011 — `@hymarkx/formatter` and `hmx fmt`

**Phase:** 7 · **Assignee:** Codex · **Status:** in progress

## CONTEXT

language server formats through it.

Binding: `docs/adr/0015-developer-experience.md` (decides the policy — read it first),
`SPEC.md`, `CLAUDE.md`.

## OBJECTIVE

`hmx fmt` produces a canonical form of HMX constructs, leaves prose untouched, fixes
container fence counts, and is idempotent.

## REQUIREMENTS

### 1. New package

`packages/formatter` → `@hymarkx/formatter`. Depends on `@hymarkx/ast` and
`@hymarkx/parser`. May **not** import micromark, mdast, or unified directly — the boundary
check enforces this. No filesystem access; the CLI does I/O.

```ts
export interface FormatOptions {
  /** File path used in diagnostics. */
  readonly from?: string
}

export interface FormatResult {
  /** Formatted source. Equals the input when nothing needed changing. */
  readonly source: string
  /** True when `source` differs from the input. */
  readonly changed: boolean
  readonly diagnostics: readonly Diagnostic[]
}

export function format(source: string, options?: FormatOptions): FormatResult
```

### 2. What the formatter changes

**Only HMX constructs.** Everything else is copied through byte for byte.

- **Container fence counts.** A container whose children include a container with the same or
  greater colon count gets its fence widened until nesting is correct. This is the trap from
  `BACKLOG.md`: `:::grid` wrapping `:::metric` silently closes the outer container, and
  fixing it automatically is the single strongest reason this tool exists.
- **Directive attributes.** One space between attributes, none inside the braces, `#id` and
  `.class` shorthands kept as written and ordered first, `key="value"` with double quotes
  unless the value contains a double quote.
- **Expression spacing.** `{{title}}` → `{{ title }}`; one space inside the braces, operators
  spaced per the expression grammar, no trailing space.
- **Frontmatter.** Two-space indentation, one space after `:`. **Key order is preserved** —
  reordering keys is a semantic-looking change the author did not ask for.
- **Trailing whitespace** on lines containing an HMX construct, and a single trailing newline
  at end of file.

### 3. What the formatter MUST NOT change

Stated as requirements because each is a plausible "improvement" that would be wrong:

- paragraph wrapping or line length
- list markers, numbering, or indentation of plain Markdown
- emphasis or strong markers (`*` vs `_`)
- heading style (ATX vs setext)
- code block content or fence style
- link reference definitions or their order
- blank lines between blocks
- the contents of `<style>`, `<script>`, or raw HTML
- frontmatter key order or value formatting beyond indentation

A document containing no HMX construct MUST come back **byte-identical**. Assert this
against the CommonMark corpus: formatting all 652 examples must change none of them.

### 4. Idempotence and determinism

`format(format(x)) === format(x)` for every input. Assert it across the whole fixture corpus
and the CommonMark suite, not on a handful of cases — idempotence bugs hide in the cases
nobody thought to write.

Formatting must never change a document's *meaning*: for every fixture, compiling the
formatted source must produce the same HTML as compiling the original. This is the real
safety property and it must be a test.

### 5. Malformed input

A document with unclosed containers or invalid expressions cannot be formatted safely.
Return the source unchanged with `changed: false`, passing the parse diagnostics through.
**Never emit a partially formatted document** — a formatter that mangles broken files is
worse than one that declines.

### 6. CLI

```
hmx fmt <input...> [--check] [--json]
```

- Default rewrites files in place, reporting `formatted N files, M changed` on stderr.
- `--check` writes nothing and exits `1` if any file would change — the CI mode. List which.
- `--json` prints `{ files: [{ path, changed }] }`.
- Exit codes match the existing convention: `0` clean, `1` changes needed under `--check` or
  error diagnostics, `2` usage or I/O failure.
- Reuse the existing path-traversal guard.

### 7. Tests

- Fence-count fixing: two levels, three levels, already-correct input left alone.
- Each attribute normalisation, including a value containing a double quote.
- Expression spacing, including operators and nested member access.
- Frontmatter indentation with key order preserved.
- **All 652 CommonMark examples format to themselves byte-identically.**
- Idempotence across every fixture in `fixtures/`.
- Meaning preservation: formatted source compiles to identical HTML for every fixture.
- Malformed input returns unchanged with diagnostics.
- CRLF input: line endings preserved as they were, not normalised on write.
- `--check` exit codes.

### 8. Guide

Add a short `docs/guides/formatting.md` stating what the formatter does and — with reasons —

## NON-GOALS

1. No prose reflowing, ever (ADR-0015).
2. No configuration or options. A formatter with a style config is a style argument with
   extra steps; the canonical form is the canonical form.
3. No editor integration — that is HMX-013.
4. No parser or AST change.
5. No `--write`/`--stdin` variants beyond those specified.

## EDGE CASES

- A directive inside a blockquote or list item — indentation must be preserved exactly.
- A fence needing widening whose parent then also needs widening.
- `{{` inside a code span, which must not be treated as an expression.
- A document that is only frontmatter.
- An empty file, and a file of only whitespace.
- A file already correctly formatted: `changed` must be `false`, not `true` with identical
  output.
