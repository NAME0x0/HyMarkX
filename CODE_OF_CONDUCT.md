# Code of Conduct

## The short version

Be straightforward and be kind. Criticise work, not people. Assume the other person is trying
to get it right.

## Scope

This applies to issues, pull requests, discussions, commit messages, and any other space that
represents the project.

## What is expected

- **Argue from evidence.** "This is slower" invites a benchmark; "this feels slow" does not.
  The project holds itself to measuring before claiming, and reviews work the same way.
- **Say what you actually think.** A review that withholds a real objection to stay pleasant
  wastes everyone's time, including the author's.
- **Accept a decision once it is made.** Disagreeing, being heard, and then continuing anyway
  is a normal outcome. Relitigating a settled decision in every subsequent thread is not.
- **Take correction plainly.** Being wrong in public is ordinary. Own it, fix it, move on.

## What is not acceptable

Harassment, insults, and personal attacks. Discrimination or demeaning comments about anyone's
identity or background. Sexualised language or imagery. Publishing others' private information
without permission. Sustained disruption of discussion. Deliberately submitting malicious code
or dependencies.

## Reporting

Report by opening an issue, or by contacting the maintainer directly if the report should not
be public. Reports will be reviewed and acted on. The maintainer of this project is currently
one person, so a response may not be immediate — it will come.

## Enforcement

Depending on severity and repetition: a request to stop, a warning, temporary restriction from
interacting with the project, or a permanent ban. Deliberately malicious contributions go
straight to the last one.
